# API examples and curl commands

The curl commands use `--fail-with-body` (curl 7.76 or later) to preserve error
bodies while returning a failure status. In shell automation, enable `set -o pipefail`
so a failing curl is not hidden by a successful JSON formatter.

Run these examples from the repository root against a dedicated local server.
They change shared simulation state. Install `jq` for the response formatting
shown below, or replace `| jq` with `| python3 -m json.tool`.

A successful HTTP request is not always a completed operation. In particular,
starting a run returns 202 while preparation continues. The
[Python walkthrough](client-walkthrough.md) demonstrates bounded polling and
verification in a complete client.

## 1. Check Server Health & SUMO Engine Status
```bash
curl --fail-with-body --silent --show-error http://127.0.0.1:8090/health | jq
curl --fail-with-body --silent --show-error http://127.0.0.1:8090/api/v1/system/info | jq
```

Health checks HTTP availability. System information reports capabilities such as
SUMO availability; a healthy server can still have no active simulation.

## 2. Start a 20-Minute (1200s) Weekday Simulation
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/playback/start \
  -H "Content-Type: application/json" \
  -H "X-DSTNS-Operator: $(cat logs/operator.token)" \
  -d '{
    "seed": "0x123456789ABCDEF0",
    "playback_duration_seconds": 1200,
    "day": 0,
    "tick_rate": 1.0,
    "modules": {"traffic": true, "signals": true, "buildings": true, "dws": true},
    "dws": {"frequency": 4}
  }' | jq
```

The header reads the credential generated by this server; use the actual logs
directory if it differs. Avoid shell tracing or verbose request logs that reveal
the header. The seed is a string to preserve integer precision. Day `0` selects a
weekday, and 1,200 wall-clock seconds is the requested day duration at 1x. This
example uses automatic map selection and may need network access. Poll
`GET /api/v1/playback/status` until `data.lifecycle` is `RUNNING`, or inspect
`data.preparation_error` if it returns to `IDLE`. Starting while a run is active
returns 409; do not reset another operator's run just to retry.

## 3. Pause Simulation
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/playback/pause | jq
```

Pause before collecting a stable snapshot or seeking to a precise time.
Check that the returned lifecycle is `PAUSED` before continuing.

## 4. Seek to 15:30:00 (55,800 virtual seconds)
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/playback/seek \
  -H "Content-Type: application/json" \
  -d '{"target_time": "15:30:00"}' | jq
```

The target is virtual time, not elapsed wall time. After the preceding pause,
seek keeps the run paused at 55,800 seconds. Seeking an already running run may
resume it; use the pause sequence when you need a stable target.

## 5. Adjust Tick Rate to 0.5x
```bash
curl --fail-with-body --silent --show-error -X PUT http://127.0.0.1:8090/api/v1/control/tick-rate \
  -H "Content-Type: application/json" \
  -d '{"tick_rate": 0.5}' | jq
```

A tick rate of 0.5 requests half-speed playback. Adaptive backpressure can further
limit applied speed, so distinguish the requested rate from observed progression.

## 6. Inject Manual Weather Event
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/control/events/weather \
  -H "Content-Type: application/json" \
  -d '{
    "epicenter_node": 10,
    "intensity": 0.8,
    "radius_m": 750,
    "duration_virtual_minutes": 30,
    "flood_gain": 0.6
  }' | jq
```

The epicenter must be a node in the current topology; replace `10` with an ID
obtained from `/api/v1/view/topology`. Intensity and flood gain are normalized
values; the radius is metres and duration is virtual minutes. Inspect subsequent
weather views or events to observe the accepted control.

## 7. Export SUMO Scenario XML Bundle
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/export/sumo \
  -H "Content-Type: application/json" \
  -d '{"directory": "data/sumo_export"}' | jq
```

The path is on the server filesystem, not the curl client. The server writes with
its own permissions. Use an intended export directory, keep the endpoint within
the trusted access boundary, and retain the returned export result.

## 8. Run SUMO Microscopic Physics Simulation
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/system/sumo-simulate \
  -H "Content-Type: application/json" \
  -d '{"directory": "data/sumo_run", "begin_s": 0, "end_s": 3600}' | jq
```

This requires working `sumo` and `netconvert` executables on the server. The
interval is in virtual seconds. SUMO is a separate batch calculation and does
not update the live DSTNS world.

## 9. Graceful Termination
```bash
curl --fail-with-body --silent --show-error -X POST http://127.0.0.1:8090/api/v1/system/terminate | jq
```

Termination exits the server process. Subsequent requests may fail to connect.
A supervisor or container restart policy can restart it; use the supervisor's
stop command when shutdown must persist.
