# System API

Service identity, health, the compute backend, map and preparation progress,
backpressure, observer configuration, the source offer, SUMO and shutdown. Routes are under
`/api/v1/system` unless noted.

| Method | Route | Purpose |
|---|---|---|
| GET | `/health`, `/api/v1/system/health` | Liveness and lifecycle; answers even while a map downloads |
| GET | `/info` | Version, compiler, SUMO availability and the compute backend |
| GET | `/compute` | The compute backends in detail: device, selection, calibration, step timing, fallbacks |
| GET | `/status` | The full run status (same as `/playback/status`) |
| GET | `/endpoints`, `/api/v1` | The route index, generated by the server |
| GET | `/map-status` | The download and preparation in progress |
| GET | `/observer` | Whether the observer page has loaded |
| GET, POST | `/backpressure` | Read, or report to, Adaptive Simulation Backpressure |
| GET | `/ui-config` | The observer's starting configuration |
| GET | `/source` | The AGPL source offer |
| POST | `/sumo-simulate` | Export, build and run SUMO ([SUMO adapter](../components/sumo-adapter.md)) |
| POST | `/terminate`, `/terminate` (root) | Stop the run and exit the process |

## GET /health

```json
{ "ok": true, "service": "dstns", "product": "Deterministic Spatiotemporal Transport Network Simulator",
  "version": "2.2.0", "observer_ui_version": "observer-v2", "lifecycle": "RUNNING" }
```

Lock-free: it reads a mirror of the lifecycle, so it answers instantly even
while a compilation holds the engine for a minute-long download. Use it for
health checks and readiness probes. `service == "dstns"` identifies a DSTNS
server; the CLI uses `observer_ui_version` to tell a current server from an
older one on the same port.

## GET /info

```json
{
  "ok": true, "service": "dstns", "version": "2.2.0", "lifecycle": "PAUSED",
  "build": { "compiler": "Apple LLVM 21.0.0 (clang-2100.3.34.2)", "cpp_standard": 202002 },
  "sumo": { "available": true, "version": "1.15.0", "sumo_binary": "/usr/bin/sumo",
            "netconvert_binary": "/usr/bin/netconvert", "sumo_home": "/usr" },
  "compute": {
    "requested_backend": "auto", "active_backend": "cpu", "fallback_backend": "cpu",
    "health": { "cpu": "active", "vulkan": "available" },
    "selection_reason": "the world (1196 nodes, 2554 edges) is below the accelerator threshold; the CPU is faster at this size",
    "fallback_reason": null, "vulkan_compiled": true, "vulkan_available": true, "deterministic": true,
    "device": { "name": "Apple M4", "vendor": "Apple", "type": "integrated", "api_version": "1.3.357",
                "driver": "MoltenVK", "driver_version": "1.4.2", "memory_bytes": 25769803776,
                "moltenvk": true, "portability_subset": true, "software": false,
                "compute_queue_family": 0, "workgroup_size": 128, "timestamps": true,
                "validation": false, "pipeline_cache": "warm", "uuid": "0000106b-1b00-0209-0000-000000000000" },
    "shader_bundle": { "sha256": "…", "compiler": "Glslang Version: 11:16.6.0", "shaders": [ … ] },
    "details": "/api/v1/system/compute"
  }
}
```

`sumo.available` is true only if both `sumo` and `netconvert` start and answer
`--version`. Detection runs on every call, so installing or repairing SUMO is
picked up without a restart.

`compute` says which hardware runs the physics. It is descriptive: the state
the API serves is identical on every backend, and no client needs it to
interpret anything. `health` gives each backend's state: `unavailable` (no
usable device), `disabled` (by configuration), `available`, `active`,
`degraded`, or `failed` (it failed during this process and will not be
retried). `device` is null when Vulkan is unavailable, with the reason in
`fallback_reason`. No filesystem path is reported.

## GET /compute

`{"ok": true, "api_version": "1.0", "data": {...}}`, where `data` has
everything under `compute` above and:

| Field | Meaning |
|---|---|
| `workload` | The installed world's nodes, edges and signals |
| `thresholds` | `auto` mode's size thresholds, and whether it calibrates |
| `calibration` | When `auto` timed both backends on this world: `cpu_ms`, `vulkan_ms` per step and the `chosen` one |
| `step` | The last step: `backend`, `total_ms`, `cpu_ms` (host time), `gpu_ms` (device time from timestamp queries), `upload_bytes`, `readback_bytes`, `dispatches`, and `passes` (device time per pass: upload, nodes, edges, readback) |
| `totals` | Steps run on each backend and their mean time, fallbacks, verified steps, full state downloads, journal replays, bytes moved |
| `memory` | Host state size, and an estimate of device memory in use |
| `cpu` | CPU backend threads, and the edge count above which they are used |
| `last_failure` | Why Vulkan last failed, or null |
| `options` | The resolved compute options (no paths) |

If a request arrives while the engine is recovering from a lost GPU it is
answered `503` with code `COMPUTE_RECOVERING`; retry after a moment.

## GET /map-status

```json
{ "api_version": "1.0", "data": {
    "active": true, "preparation": "acquiring",
    "city": "Dar es Salaam", "country": "Tanzania",
    "phase": "download", "bytes": 23592960, "total": 0, "elapsed_s": 14.2 } }
```

| Field | Meaning |
|---|---|
| `preparation` | What a compilation is doing: `selecting` (seed to place), `acquiring` (getting the map), `building` (graph, signals, schedules), or empty |
| `active` | A download is running |
| `phase` | `connect`, `download`, `parse` (validating) or `retry` |
| `bytes`, `total` | Progress; `total` is 0 when the server did not announce a size |

Readable while a compilation holds the engine lock: this is what lets the
observer and `dstns-run` narrate start-up.

## GET /observer

`{"data": {"loaded": true, "loads": 5}}`: how many times the observer page has
been served. The CLI opens the browser and waits for `loaded` before starting a
run, so preparation is watched rather than hidden.

## Backpressure

`GET /backpressure` returns the controller's state; `POST /backpressure` is how
the observer reports its health once a second, and returns the same state:

```json
POST /api/v1/system/backpressure
{ "virtual_lag_s": 2.4, "client_frame_s": 0.018, "since_poll_s": 1.02 }
```

```json
{ "state": "NORMAL", "score": 0.12, "raw_score": 0.1, "synced": true,
  "rate_locked": false, "motion_locked": false, "gui_suspended": false,
  "rate_capped": false, "rate_cap": 0.0,
  "applied_tick_rate": 1.0, "requested_tick_rate": 1.0,
  "stressed_for_s": 0.0, "state_for_s": 2741.5,
  "throughput": { "snapshots_per_s": 1.0, "bytes_per_s": 182000 },
  "actions": [ { "action": "throttle", "reason": "observer behind; reducing the rate ceiling to close the gap",
                 "score": 0.65, "rate_before": -1.0, "rate_after": 1.0, "at_s": 15.37 } ],
  "thresholds": { "synced": 0.35, "stressed": 0.6, "critical": 0.85,
                  "escalate_after_s": 3.0, "restricted_hold_s": 5.0, "recover_after_s": 3.0 } }
```

All three report values must be finite and non-negative (400 otherwise). A
rate of `-1.0` in `actions` means "uncapped". See [Adaptive
backpressure](../concepts/backpressure.md).

## GET /ui-config

The contents of `config/ui-config.json`, wrapped as `{"data": {...}}`; an empty
object if the file is absent. A malformed file returns 500
`UI_CONFIG_INVALID` and the observer falls back to its built-in defaults. See
[Observer configuration](../guide/observer-configuration.md).

## GET /source

The AGPL section 13 source offer: program, version, copyright, licence and
URL, and the map data's attribution (OpenStreetMap contributors, ODbL 1.0).
The observer links to it from About.

## POST /terminate

```json
{ "ok": true, "status": "TERMINATING", "message": "DSTNS server is shutting down gracefully." }
```

Stops the run, kills any map download's whole process group, stops the
listener after 150 ms, and exits with status 0, at most 3 seconds later
whatever else is in flight. `POST` only: there is no `GET` form, because a GET
could be triggered from any web page. In Docker, the container stops.
