# Code evaluation, October 2026

A review of the `dstns-v2` branch as published at `bc6e517` ("UI Changes
(Unstable)"), covering the C++ engine, the HTTP platform, the SUMO adapter, the
OSM loader, the observer interface and the operator CLI. This page records what
was examined, every defect found and how it was fixed, the tests that now guard
each fix, and the issues that were found but deliberately left alone.


## Starting point

At `bc6e517` the build was clean apart from one unused-function warning, and
the native suites passed. Two suites did not:

| Suite | Result at `bc6e517` | Cause |
|---|---|---|
| `ui-engine` (Vitest) | 1 of 283 failed | A real defect: dialogs opened from the completion screen were removed 180 ms later (see U1) |
| `tests/api/api_smoke.py` | Failed at step 22 | SUMO reported as available when its `netconvert` could not start (see S2) |

Every other suite passed: 13 CTest targets, the CLI artifact test, the OSM
fetch and saved-seed suites, the loading and termination HTTP suites, and the
launcher end-to-end test.

## Method

1. Build from a clean configure and run every suite listed in
   [TESTING.md](testing.md) to establish the baseline above.
2. Read the engine (`src/engine.cpp`), HTTP layer (`src/api.cpp`), SUMO bridge,
   OSM loader, downloader, logger and server entry point line by line; read the
   observer's API client, polling hook, dialog state and auto-focus logic; read
   the CLI's validation, process management and server launch.
3. For each suspected defect, write a test that fails on the original code and
   passes on the fix. Where a test was added, it was run against the original
   source to confirm it catches the defect.
4. Re-run every suite after each group of fixes.

## Defects fixed

Severity is one of **High** (security or data loss), **Medium** (wrong
results or a broken feature) or **Low** (edge cases, diagnostics, hygiene).

### Observer interface

| ID | Severity | Defect | Fix | Guarded by |
|---|---|---|---|---|
| U1 | Medium | `closeDialog()` schedules the open dialog to be cleared after its 180 ms exit transition. The completion screen called it and then opened the next dialog, so the pending clear removed the new one: "Generate a new world" flashed its confirm and lost it, and any dialog opened within 180 ms of another closing went the same way. | The pending clear is held in a ref; every dialog trigger goes through `openDialog`, which cancels it. "Restart same simulation" asks through the reset confirm, and a confirmed reset of a finished day plays immediately. | `appShell.test.tsx`: both completion actions now assert the confirm is still present 400 ms later, since `findByRole` polls and would catch a dialog that existed for 180 ms. |
| U2 | Low | The API client parsed JSON before checking the status, so a non-JSON error response (a proxy's 502, an empty 404) was reported as "unreadable response". | Non-JSON error responses report `Request failed (<status>)`. | `api.test.ts` |

### HTTP platform and security

| ID | Severity | Defect | Fix | Guarded by |
|---|---|---|---|---|
| P1 | High | Cross-site request forgery. CORS allowed any origin and no request was checked for where it came from, so any web page the operator visited could pause, seek, override roads or shut the server down with an ordinary form post or `fetch`. | State-changing requests (anything but `GET`, `HEAD`, `OPTIONS`) that carry a browser `Origin` must match the `Host` (or `X-Forwarded-Host`) they were sent to, or appear in `DSTNS_ALLOWED_ORIGINS`; otherwise HTTP 403 `CROSS_ORIGIN_FORBIDDEN`. Clients that are not browsers send no `Origin` and are unaffected. The gateway now forwards `X-Forwarded-Host`. | `hardening_smoke.py` |
| P2 | High | `GET /terminate` and `GET /api/v1/system/terminate` shut the process down. A GET can be triggered by an `<img>` tag on any page, without CORS getting a say. | Termination is `POST` only. | `hardening_smoke.py` |
| P3 | Medium | Path IDs were parsed with `std::stoul` and narrowed to 32 bits, so `/control/edges/4294967296/override` silently overrode edge 0, and signal and node routes behaved likewise. | `path_id()` parses into `uint32_t` and rejects overflow with HTTP 400. | `hardening_smoke.py` |
| P4 | Medium | `time_value` range-checked signed JSON integers only. A non-negative JSON number is parsed as unsigned, so `{"target_time": 999999}` skipped the `[0, 86400]` check and was truncated. | Unsigned values are range-checked too. | `hardening_smoke.py` |
| P5 | Low | `since_news_id` and log `limit` used `std::stoull`, which accepts `-1` and wraps it to 2^64-1. | `unsigned_parameter()` rejects signs and garbage with HTTP 400. | `hardening_smoke.py` |
| P6 | Medium | `duration_virtual_minutes` was converted from `double` to `uint32_t` unchecked; negative or very large values are undefined behaviour. | Checked as a double, in `[1, 1440]`. | `hardening_smoke.py`, `world_tests.cpp` |
| P7 | Low | `sumo-simulate` accepted any `begin_s`/`end_s`, including an end before the start. | Both are virtual-day times; `begin_s < end_s <= 86400` is required. | `hardening_smoke.py` |
| P8 | Medium | nlohmann::json converts a negative number to an unsigned type by wrapping it, so `POST /control/undo {"count": -1}` reached the engine as 4294967295 and undid the entire history. | The count is read signed and must be in [1, 10000]. Other unsigned fields wrap to values their own range checks already refuse. | `hardening_smoke.py` |

## Behaviour changes to be aware of

- **Graphs with untagged roundabouts change.** Fix O1 makes them one-way as
  OpenStreetMap intends. For any map containing one, the reverse edges become
  `synthetic_reverse`, and so `graph_hash`, `scenario_hash` and every downstream
  result change for that map. Maps without untagged roundabouts are unaffected,
  and the replay suite confirms the shipped fixtures are unchanged.
- **Browser clients on another origin must be allow-listed.** A UI served from
  a different origin than the API (for example with `VITE_DSTNS_API_URL`
  pointing elsewhere) must have that origin in `DSTNS_ALLOWED_ORIGINS`. The
  Vite dev server proxies `/api`, so the default development setup is
  same-origin and needs nothing.
- **Shutdown is POST only.** Scripts that used `curl http://.../terminate`
  must use `curl -X POST`.
- **"Restart same simulation" now asks first**, through the same reset confirm
  as the command rail.

## Known issues not changed

These were found during the review and left alone, because the fix belongs to
a design decision rather than a defect, or the risk is negligible:

- **CORS still answers `Access-Control-Allow-Origin: *`.** With P1 in place
  this only lets other pages *read* run state, which is not sensitive. Tighten
  it if run data becomes confidential.
- **The SUMO export and simulate endpoints write wherever `directory` points.**
  They are operator tools on a local server; the shell-injection risk is closed
  (S1), but the endpoints are not sandboxed to a directory.
- **A* routing assumes speeds no higher than 33.33 m/s.** An operator speed
  multiplier above about 1.1 on a motorway exceeds that, making the heuristic
  inadmissible, and routes may then be slightly suboptimal. Routes stay valid.
- **The CLI always talks to `127.0.0.1`.** If `api.host` is set to a specific
  non-loopback interface, the CLI's health checks will not reach it.
- **A self-closing `<way/>` in OSM XML** would make the tokenizer pair it with
  the next way's closing tag. Overpass never emits these for road queries.
